# Salesforce Dev Org Build Plan — Sales Cloud + Revenue Cloud

**Goal:** Build a learning-focused Salesforce org that demonstrates a realistic B2B SaaS quote-to-cash flow: Lead → Account/Contact → Opportunity → Product Catalog → Quote, using Sales Cloud and the new Revenue Cloud (Revenue Lifecycle Management / RLM).

**Scope decisions (locked in for this build):**
| Decision | Choice |
|---|---|
| Purpose | Learning / skills practice |
| Revenue Cloud generation | New unified Revenue Lifecycle Management (RLM) — not legacy Salesforce CPQ |
| Process depth | Lead → Opportunity → Quote (no Orders/Contracts/Billing in v1) |
| Business model | B2B SaaS subscriptions (tiered plans + usage add-ons) |
| Trial org | Communications Cloud Free Trial **on Salesforce Platform** (pre-configured, "powered by Revenue Cloud") — see Phase 0 note below |
| Execution method | Salesforce CLI (`sf`), metadata-driven |

**Note on the trial org:** As of Oct 2026, Salesforce has no standalone "Revenue Cloud" free trial — Revenue Cloud (RLM) is only exposed through industry-cloud trials built on top of it. We're using the **Communications Cloud Free Trial on Salesforce Platform** (confirmed live at `developer.salesforce.com/free-trials/comparison/communications-cloud`), the pre-configured variant with sample telecom data and feature-discovery navigation. Telecom plans (recurring + usage charges, bundles) map closely to our B2B SaaS subscription model, so Phase 3/5 below will **repurpose/extend the pre-loaded sample catalog** rather than building one fully from scratch — flagged inline where that applies.

## Testing Strategy

Every phase gets its own automated regression test script, and **a full regression run is required at the end of every phase before moving to the next one** — not just a check of what that phase added, but a re-check of everything built so far, so a later phase can't silently break an earlier one.

**Layout:**
```
testing/
  lib/assert.sh              # shared pass/fail assertion helpers
  phase0_provisioning.sh     # test cases for Phase 0
  phase1_org_baseline.sh     # test cases for Phase 1
  phaseN_<name>.sh           # one file per phase, added as that phase is built
  run_regression.sh          # runs every phaseN_*.sh in order, cumulative pass/fail summary
```

**How it works:**
- Each `phaseN_*.sh` script is a standalone, re-runnable suite of test cases (`TC-N.x`) that query the live org via `sf` CLI (`sf data query`, `sf sobject list`, Tooling API `EntityDefinition` queries, etc.) and assert the expected state — not a record of what we *did*, but a check of what's *true right now*.
- `testing/lib/assert.sh` provides `assert_eq`, `assert_not_empty`, `assert_contains`, `assert_gte`, and `print_summary`. Each phase script sources it, runs its checks, and exits non-zero if anything failed.
- `testing/run_regression.sh` discovers and runs every phase script in order and prints a combined summary — this is **the full regression test**, run at the close of each phase.
- Tests are state-based, not transcript-based: they verify the org's actual current configuration (roles, sharing model, catalog records, flows, etc.), so they'll catch drift even if a later phase's deploy accidentally reverts something.

**Process rule going forward:** after completing a phase's build work, (1) write/extend that phase's `testing/phaseN_*.sh` with test cases covering what was just built, (2) run `./testing/run_regression.sh`, and (3) don't start the next phase until it's 100% green. Failures get fixed before moving on, not deferred.

**Run it yourself any time:**
```
cd "Salesforce Dev"
./testing/run_regression.sh
```

## Phase 4 — CPQ / Quoting ✅ Complete (2026-10-10)

- [x] Enable Quote on Opportunity — Quote `Acme Growth Plan Quote` created against Opportunity "Acme - Growth Plan Subscription" (Account: Acme), Standard Price Book.
- [x] Quote Line Editor: 3 lines added (Growth Plan bundle parent @ 20% discount, Premium Support Add-on, Implementation Fee one-time fee) — **not** added via Browse Catalogs (see root-cause finding below); inserted directly via `QuoteLineItem` records against existing `PricebookEntry`/`Product2` data, then verified rendering correctly in the actual Quote Line Editor UI after a required "Refresh." True parent/child bundle line linkage (`ParentQuoteLineItemId`) turned out to be a platform-managed, non-writable field — can only be set by the Configurator engine (the same broken Browse Catalogs/Product Discovery path), so the bundle's components exist as sibling lines on the quote rather than a modeled parent/child hierarchy. Usage-based line (API Usage Add-on) was **deferred** — inserting it threw `FIELD_INTEGRITY_EXCEPTION` requiring "commitment products/grants/policies" to be defined first, which is a deeper piece of RLM's usage-billing module out of scope here.
- [x] **Approval Process**: "High Discount Quote Approval" built via Setup UI (Standard Wizard — hand-written metadata XML for `ApprovalProcess` was judged too failure-prone to author blind) on `Quote`, entry criteria `Discount > 15`, single step, approver = the org's one admin user (self-approval — same single-license constraint noted since Phase 1). Functionally tested both directions: a 25%-discount test quote was submitted → `Pending` → approved → `Approved`; the 20%-discount quote above blends to **3.98%** org-wide discount (only one of its 3 lines is discounted) and correctly throws `NO_APPLICABLE_PROCESS` on submission, confirming the threshold logic works on the Quote's aggregate `Discount` field, not just a single line.
- [~] **Quote Template**: Setup > Quote Templates offers a working editor and ships an auto-generated, Active "Standard Template" with all expected sections (org address, line items, totals, terms) and RLM's Quote fields render correctly in the field palette — but clicking "Save and Preview" to actually render a PDF throws a generic Salesforce platform **internal server error** (Error ID logged, not actionable from our side). This looks like classic Visualforce Quote Templates aren't fully compatible with RLM's enhanced Quote object in this org; RLM's intended path for quote documents is DocGen (OmniStudio), which has its own permission sets already assigned to the admin user but is a materially bigger feature to stand up and out of scope for this pass. Treating this as a documented platform limitation, not a fix we're pursuing further right now.
- [x] Sync Quote → Opportunity — used the UI's "Start Sync" action (the `Quote.IsSyncing` field is platform-managed and rejected direct API writes). Fully native, zero custom code: `Opportunity.SyncedQuoteId` populated, `Opportunity.Amount` (£718.20) matched the Quote's `GrandTotal` exactly, and all 3 `OpportunityLineItem` records were created automatically. As a bonus integration check, moved the Opportunity to the "Quote Sent" stage afterward and confirmed Phase 2's `Quote_Sent_Requires_Quote` validation rule correctly allows it now that `SyncedQuoteId` is populated (it would have blocked this before the sync).
- [x] **Testing:** `testing/phase4_cpq_quoting.sh` written (16 test cases covering the Opportunity/Quote/line-item build, the discount-based approval process in both directions, and native Quote↔Opportunity sync). Hit the same echoed-Apex-source `grep -o` bug as Phase 2's TC-2.14 in the negative-approval test — fixed the same way, by scoping the grep to the `USER_DEBUG` line. Full regression run (Phase 0–4): **PASS (93/93 test cases)**.

**Root cause of the Browse Catalogs issue (carried over from the Phase 3 log), now confirmed:** Setup > Feature Settings > Product Catalog Management > Product Discovery > Product Discovery Settings > "Default Product Discovery Procedure Plan Definition Template" has two required `Procedure Plan Sections` — `ProductQualificationProcedure` and `PricingProcedure` — and **both have an empty, unconfigured required `Procedure` field**. Clicking "Refresh" on a Quote's Lines tab now surfaces this directly: *"Something went wrong while validating the configured bundle...Ensure that the Product Discovery is set up correctly, or refresh the Decision Tables and try again."* This is why Browse Catalogs returns zero products for **every** catalog in the org, including pre-existing ones we never touched — the qualification/pricing engine that powers product browsing was never wired up to an actual Decision Table/Expression Set in this trial org, independent of any catalog data. Actually building that Procedure is a substantial piece of Revenue Cloud rule-engine authoring (Decision Tables under Setup > Rule Engine), not a quick config fix, so it's being left as a documented, root-caused gap rather than built out in this pass — Phase 4's quoting work was unblocked instead by inserting `QuoteLineItem` records directly, which is fully supported and exercises the same pricing/discount/approval/sync mechanics.
